## Context
现有网页由应用内 HTTP 服务提供，固定端口 8000，应用启动时自动开启，无口令。服务仅接受最大 1024 字节的 JSON 请求，单线程处理连接，并有 3 秒请求期限，不能直接复用于图片上传。

`FirstFragment` 从 MediaStore 查询并随机选择图片，单图模式缓存多张图片。现有目录扫描和存储广播不能保证新上传的每个文件立即被重新加载，需要在图片完成发布后主动通知播放器并清理缓存。

## Goals / Non-Goals
- Goals: 从网页选择文件或文件夹上传图片到存储卡公开目录，显示结果，相册运行中自动发现新图片。
- Non-Goals: 视频上传、压缩包解压、覆盖或删除已有图片、保留客户端文件夹层次、图片强制置顶及互联网文件服务。

## Decisions
- 网页提供“选择图片”和“选择文件夹”两个入口。前者支持 multiple，后者在支持的浏览器中递归枚举文件。按文件建立队列，顺序发送，每项独立报告结果，单项失败后继续其他项，支持重试失败项。
- 每个文件独立 POST 二进制数据，文件名作为编码后的元数据传递，不在内存中构造整批请求。使用可报告上传进度的浏览器请求；仅服务器确认落盘并发布后显示该文件上传完成。
- 新增目标目录信息与上传接口。文件上传前校验同源来源、Content-Length、大小上限、文件名及目标卷可用性；保留已有设置 API 的小 JSON 请求限制。
- 采用有界工作线程和连接队列，单个上传连接使用独立的空闲超时及总时限，使上传不长期占用设置读取与保存。关闭服务时关闭正在处理的连接并清理未完成项目。
- Android 10 及以上通过 `MediaStore.getExternalVolumeNames()` 发现存储卷，在选定可移除卷的 Images 集合中创建条目，使用 `RELATIVE_PATH=Pictures/GalleryUploads/` 和 `IS_PENDING=1` 写入。完成验证后解除 pending，将已完成图片发布到媒体库；失败删除本次新建条目。
- 不通过任意客户端路径写文件。仅使用基础文件名，拒绝路径穿越、控制字符和非法名称。同名另存，不覆盖；先验证格式和图片尺寸元数据，发布前确保内容确实是支持的图片，避免按完整尺寸解码大图。
- Android 9 及以下使用可写共享图片目录及 MediaScannerConnection；如果存储卡权限不足，明确提示需要在设备上授权对应目录，不使用私有缓存目录替代公开图片目录。
- 当前目标设备为 Android 11，优先验证该路径；无需为上传新增全盘管理权限。
- 发布成功后向主线程发送应用内部媒体变更通知。播放视图按生命周期注册、注销；批量完成事件进行短时间合并，清理单图列表、重置加载重试状态并重新查询 MediaStore。新图加入现有随机轮播规则，不承诺每张上传图片立即强制展示。
- 对 pending、索引失败和视图销毁分别处理；未完成图片不进入播放列表，已保存但未能刷新时提示真实状态。

## Risks / Trade-offs
- 浏览器对文件夹选择的支持不同：做能力检测，保留普通多文件选择。
- 卡拔出、只读、空间不足或传输断开：逐项失败反馈、清理本次未完成条目，不影响此前成功项目。
- 多文件刷新可能打断播放：对发布事件合并处理，避免每个数据块触发刷新。
- 旧版 Android 的可移除存储写入限制不同：不宣称对所有旧设备均能直接写入，按可用权限反馈；目标实机优先验收。

## Migration Plan
无需迁移设置或已有媒体；首次成功上传时创建目标目录。原设置读取和保存继续复用现有 API。实施完成后构建、覆盖安装到当前设备并验证上传与索引。
