## Context
应用为 Java Android 单 Activity 项目，目前通过 `SettingsDialog` 写入 `gallery_settings`，通过回调更新 `FirstFragment` 的轮播计时和布局。尚无 HTTP 服务或网页资源；本机设置与播放页的默认间隔存在差异。

## Goals / Non-Goals
- Goals: 用浏览器输入 Android 设备网址配置全部现有设置，保存后同步至播放界面，并保留本机设置能力。
- Non-Goals: 公网访问、媒体上传、远程文件管理、后台常驻和独立网站部署。

## Decisions
- 采用设备内置 HTTP 服务，同一局域网的浏览器直接访问，用户已确认此访问范围。
- 将偏好键、间隔选项、默认值和保存校验集中至共享设置组件。本机与网页使用同一保存入口，一次写入两项设置；已有有效值保持不变。
- 以主线程设置变更通知驱动播放界面的刷新，避免网络线程直接操作 Android 视图；视图销毁后解除监听。
- 网页静态资源内置到 APK，不依赖 CDN。提供页面入口、读取设置和保存设置接口；保存使用 POST，请求参数必须在既有枚举范围内。
- 服务由 Activity 管理，在应用启动时自动监听固定端口 8000，随 Activity 销毁停止。端口占用、无可用网络时显示明确状态，不展示无效地址；网络变化后重新获取可用地址。
- 应用启动时默认开启服务，按用户要求不使用口令认证。打开网页自动读取设置，不允许跨域访问；保存请求校验来源。限制请求大小与读取时间，服务只提供明确声明的页面和接口。
- HTTP 适用于可信局域网，不提供公网暴露能力。开启状态及服务失败状态在设置对话框可见。

## Risks / Trade-offs
- 局域网可能启用客户端隔离，浏览器无法连接设备：提供同网连接说明和实际可用地址。
- 设备地址可能变化：设置对话框按当前网络刷新地址，网页断开时提示重新查看设备网址。
- HTTP 不加密：限可信局域网使用，通过同源检查限制跨站操作。
- 应用被系统终止后网址不可访问：明确服务生命周期，不引入后台服务。
- 共享通知可能导致重复刷新：本机保存回调与偏好监听合并为同一刷新路径，整组设置保存一次。

## Migration Plan
复用原偏好文件和键；只对从未设置过间隔的设备统一使用 5 分钟默认值。关闭网页服务可随时恢复仅本机配置的使用方式。

## Open Questions
- 无；用户已确认同一 Wi-Fi／局域网访问。
