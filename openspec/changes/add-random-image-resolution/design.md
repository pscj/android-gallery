## Context
现有接口通过 MediaStore 选择图片并输出原图流。目标设备的 2.4GHz 链路较弱，需要按展示尺寸处理图片，同时避免原图完整解码带来的内存峰值。

## Decisions
- 沿用原有方向筛选和等概率抽样，仅处理最终选中的图片。
- HTTP 层校验成对尺寸，并使用单独的 Semaphore 串行处理带尺寸的请求；为避免慢客户端下载导致临时文件大量积压，直至该响应关闭才释放槽位。
- 将所选输入复制到应用缓存中的临时文件，避免 BitmapRegionDecoder 对非 seekable 输入的整文件内存副本。源文件最多 256 MiB，超限返回 500。
- JPEG、PNG、WebP 等支持区域解码的格式，按原始像素坐标计算中心区域（EXIF 5–8 交换目标轴），再使用采样区域解码；不支持区域解码的格式使用采样整帧解码。
- 解码结果控制在约 4,194,304 像素内，输出最多 8,388,608 像素。ARGB 解码与输出的主要 Bitmap 分配合计约 48 MiB，另有编解码器开销。高分辨率或极端宽高比可能因内存限制降低细节。
- Canvas 使用 EXIF 1–8 仿射变换一次绘制至白底目标 Bitmap，不创建额外的旋转 Bitmap。JPEG 质量固定为 85。
- 编码完成后再发送成功响应；输出保存在临时文件中，通过关闭图片流删除。失败或取消时回收 Bitmap 并清理临时文件，源图片不改变。

## Validation
JVM 测试验证 HTTP 参数、并发、错误及兼容；设备测试验证 Canvas/Bitmap、EXIF 1–8、区域解码、透明底、GIF 首帧及失败清理；目标设备 API 验证实际返回尺寸、MIME 和完整下载。
